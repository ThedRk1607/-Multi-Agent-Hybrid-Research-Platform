Imagine you have a VERY SMART FRIEND who helps you answer any question.

But this friend is EXTRA special because:

  📚  They first read ALL the books and papers you give them
      (like your school textbooks, PDFs, reports)

  🌍  If they don't find the answer in your books,
      they go search the INTERNET for you

  🤔  After they write an answer, a SECOND friend checks it
      and says "Good job!" OR "Hey, you missed this part, try again!"

  👀  And a THIRD friend is watching everything they do and
      writing notes — so you can always go back and see exactly
      what happened

  🛠️  They also carry a special TOOLBOX (called MCP) with tools like:
      - A calculator
      - A search tool
      - A summariser
      - An entity finder

That's multi agent hybrid!

In developer words:
  "A production-grade Multi-Agent AI system that answers questions
   by combining a Hybrid RAG knowledge base with live web search,
   orchestrated by LangGraph, traced by LangSmith, with MCP tools,
   and deployed free on Streamlit Cloud."

PROBLEM 1: Normal ChatGPT doesn't know YOUR files
--------------------------------------------------
  You have a 200-page company report.
  ChatGPT has never seen it.
  You ask "What was our Q3 revenue?" → ChatGPT guesses or says "I don't know"

  multi agent hybrid SOLUTION:
  You upload your report → it reads, learns, and stores it →
  now it can answer perfectly from YOUR documents

PROBLEM 2: AI makes up answers (hallucination)
-----------------------------------------------
  A normal AI sometimes invents facts that sound real but aren't.
  This is dangerous in business, medicine, law, finance.

  multi agent hybrid SOLUTION:
  Every answer is checked by a CRITIQUE AGENT.
  It compares the answer to the actual sources.
  If something is wrong → it sends the answer back for revision.
  This loop continues until the answer is genuinely correct.

PROBLEM 3: AI doesn't know today's news
----------------------------------------
  AI models have a "knowledge cutoff" — they don't know recent events.

  multi agent hybrid SOLUTION:
  A dedicated WEB SEARCH AGENT uses Tavily to fetch live internet results.
  Your answer combines your private documents PLUS the latest web information.

PROBLEM 4: You can't see what the AI is doing
----------------------------------------------
  Normal AI is a black box. You ask → it answers. You don't know HOW.

  multi agent hybrid SOLUTION:
  LangSmith traces EVERY step:
  - Which agent ran?
  - How long did it take?
  - How many tokens were used?
  - What did each agent output?
  All visible in a beautiful dashboard.

 PART 3 — HOW THE WHOLE SYSTEM WORKS (Step by Step Journey of 1 Question)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

You type:  "What were Apple's Q3 2024 earnings?"

STEP 1 — SUPERVISOR AGENT decides the plan
  "Hmm, this question is about financial data.
   I should search BOTH the knowledge base AND the web."
  → Decision: BOTH

STEP 2 — RAG AGENT searches your documents
  → Takes your question
  → Converts it to a special number pattern (embedding: [0.2, -0.5, 0.8 ...])
  → Searches Qdrant database using DENSE search (meaning-based)
  → ALSO searches using SPARSE/BM25 (keyword-based, like "Q3 2024")
  → Combines both search results (Reciprocal Rank Fusion)
  → Runs a RERANKER to pick the best 5 chunks
  → Found: "Apple Q3 2024 revenue was $85.8B..." from your PDF

STEP 3 — WEB AGENT searches the internet
  → Sends query to Tavily
  → Gets 5 live web results
  → Organises them: "According to Reuters, Apple Q3 2024..."

STEP 4 — SYNTHESIS AGENT writes the final answer
  → Gets both RAG context AND web context
  → Writes a complete, formatted, cited answer
  → Includes [RAG: apple-report.pdf/page 12] and [Web: reuters.com]

STEP 5 — CRITIQUE AGENT checks the answer
  → Reads the answer
  → Compares every claim to the source documents
  → "All facts check out. No hallucination detected."
  → Returns: GOOD ✅

STEP 6 — Answer is shown to you
  → Full markdown formatted answer
  → Source citations included
  → LangSmith trace link so you can see every detail

ENTIRE JOURNEY TAKES: ~4-8 seconds

HYBRID SEARCH — Why it's better:
  Dense only  → Finds "earnings" when you said "revenue" ✅
               Misses "Q3 2024" exact term sometimes ❌
  Sparse only → Finds "Q3 2024" exactly ✅
               Misses related concepts ❌
  HYBRID      → Finds BOTH ✅✅ via Reciprocal Rank Fusion
  Reranker    → Re-scores all results with a smarter model ✅✅✅

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

WHAT IT DOES:
  Takes 10 candidate search results → reads each one deeply alongside
  your question → scores them from most to least relevant → returns top 5.

LIKE A 5 YEAR OLD:
  You asked "best chocolate cake recipe."
  10 cookbooks are placed in front of you.
  A judge reads your question AND each cookbook page together
  and scores: "Book 3 is 9.8/10, Book 7 is 4.2/10..."
  You keep the top 5 highest-scored ones. That's reranking!

KEY CODE:
  ┌────────────────────────────────────────────────────────┐
  │  def rerank(self, query, documents):                   │
  │      pairs = [(query, doc.page_content) for doc...]   │
  │      scores = model.predict(pairs)  # cross-encoder   │
  │      sorted_docs = sorted(zip(scores, docs),          │
  │                           key=lambda x: x[0],         │
  │                           reverse=True)               │
  │      return [doc for score, doc in sorted_docs[:top_n]]│
  └────────────────────────────────────────────────────────┘

  Model used: BAAI/bge-reranker-base (runs locally, free)
  Type: Cross-Encoder (reads query + document TOGETHER — more accurate
        than bi-encoders which read them separately)

WHY IT MATTERS:
  Embedding models are FAST but approximate.
  The reranker is SLOWER but much more accurate.
  By using fast embeddings first (top 10), then slow reranking (top 5),
  we get the BEST of both worlds: speed AND accuracy.

     └────────────────────────────────────────────────┘
     This is a "shared memory" that passes between all agents.
     Each agent reads what it needs and writes what it produces.
     LangGraph automatically merges updates from each node.

  2. build_graph()  (lines 157-196)
     ┌────────────────────────────────────────────────┐
     │  graph.add_node("supervisor", supervisor_node) │
     │  graph.add_node("rag_node", rag_node)          │
     │  graph.add_node("web_node", web_node)          │
     │  graph.add_node("synthesis_node", ...)         │
     │  graph.add_node("critique_node", ...)          │
     │                                                │
     │  graph.add_edge(START, "supervisor")           │
     │  graph.add_conditional_edges(                  │
     │      "supervisor", route_supervisor, {...}     │
     │  )                                             │
     │  graph.add_edge("synthesis_node",              │
     │                  "critique_node")              │
     │  graph.add_conditional_edges(                  │
     │      "critique_node", route_critique,          │
     │      {"synthesis_node": ..., "end": END}       │
     │  )                                             │
     └────────────────────────────────────────────────┘
     This literally draws the arrows between agent boxes.
     Conditional edges = arrows that go different ways
     based on a condition (like "GOOD" vs "REVISE").

  3. SQLite Checkpointing  (lines 201-215)
     ┌────────────────────────────────────────────────┐
     │  with SqliteSaver.from_conn_string(db_path):   │
     │      graph = build_graph(checkpointer)         │
     └────────────────────────────────────────────────┘
     Every step is saved to a local SQLite database.
     This means: if the app crashes mid-way through a query,
     it can RESUME from where it stopped. Also enables
     multi-turn memory (remembers previous questions).

WHY IT MATTERS:
  Without LangGraph, you'd manually write:
    "if route == rag: call rag. if route == web: call web.
     call synthesis. call critique. if bad, loop again."
  With LangGraph:
    You draw the graph once → it handles all routing,
    state passing, loops, and parallelism automatically.

 PART 7 — KEY DESIGN CONCEPTS EXPLAINED SIMPLY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

CONCEPT 1: RAG (Retrieval-Augmented Generation)
  Normal AI: "I'll answer from my training data" → might be wrong/old
  RAG AI:    "I'll first SEARCH your actual documents, then answer" → accurate
  Like: Open-book exam vs. closed-book exam. Open-book is always more accurate.

CONCEPT 2: Hybrid Search
  Dense only  = Understanding meaning ("cat" matches "kitten") ✅
               But misses exact keywords sometimes ❌
  Sparse only = Exact keyword match ("Q3 2024") ✅
               But misses meaning ❌
  HYBRID      = Both combined via Reciprocal Rank Fusion ✅✅

CONCEPT 3: Multi-Agent System
  Single AI: One brain doing everything → gets confused, makes errors
  Multi-Agent: Specialist team, each expert at one thing → accurate results
  Like: A hospital with specialists vs. one doctor doing everything.

CONCEPT 4: LangGraph State Machine
  Old way: if/else spaghetti code → hard to debug, hard to extend
  LangGraph: Visual graph with nodes and edges → clear, scalable, testable
  Like: A flowchart vs. a wall of confusing instructions.

CONCEPT 5: LangSmith Observability
  Without it: AI is a black box. You see input → output. No idea what happened.
  With it: Every token, every decision, every tool call is logged and visible.
  Like: Flying blind vs. having a full cockpit dashboard.

CONCEPT 6: Self-Critiquing Loop
  AI writes answer → AI checks its OWN answer → AI improves if needed.
  This pattern is called "Reflection" or "Constitutional AI".
  Like: Writing an essay, then proofreading it yourself before submitting.

CONCEPT 7: MCP (Model Context Protocol)
  A standard way for AI systems to share tools.
  Like USB ports for computers — any device works with any computer.
  Any AI with MCP support (Claude, etc.) can use your tools.

CONCEPT 8: Chunking
  Documents are too large for AI to read at once.
  Solution: Break into 1,000-character pieces with 200-char overlaps.
  Overlap prevents losing meaning at chunk boundaries.
  Like: Reading a book chapter by chapter, with a reminder of the
  last page at the start of each new chapter.

  1. Push code to GitHub
  2. Go to share.streamlit.io
  3. Connect your GitHub repo
  4. Set app/main.py as entry point
  5. Add secrets (copy from .env)
  6. Click Deploy!
  Your app gets a public URL like: yourname.streamlit.app

OPTION B — Render.com (More control)
  1. render.com → New Web Service → Connect GitHub
  2. Build Command: pip install -r requirements.txt
  3. Start Command: streamlit run app/main.py --server.port $PORT --server.address 0.0.0.0
  4. Add environment variables
  5. Deploy!

OPTION C — Docker locally
  docker-compose up -d
  Open: http://localhost:8501
